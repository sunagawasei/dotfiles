# task-board

プロジェクトの `.claude/tasks/*.json` を読み、タスクの一覧をプロンプト上の帯に表示する Claude Code の mod。
表示するだけで、Task ツールの登録やプロンプトの変更はしない。エージェントの動作には影響しない。

複数セッションに作業を割り振る統括セッションで、どのタスクが進行中・待機中・完了かを人が確認する用途を想定している。

## 表示

- 帯: 見出し(`N tasks (… done, … in progress, … open)`)と、未完了の上位5件。残りは `… +N pending`。
- `/board`: 完了を含む全件を Pane に開く。もう一度 `/board` か Esc で閉じる。
- `ctrl+x t`: `/board` と同じ開閉。mod 側にキー登録 API が無いため、帯と Pane の Button の `action` に未使用のエンジンアクション `app:toggleDiffNoiseFilter` を結び、`~/.config/claude/keybindings.json` の Global にそのキーを割り当てている。
- 色と記号は標準のタスク一覧に合わせてある(`◼` 進行中、`◻` 未着手、`✔` 完了)。

## データ

セッションの作業ディレクトリの `.claude/tasks/` に、1リスト=1ファイルで置く。3秒ごとに読み直す。ファイルが複数あるときは、Pane でファイル名ごとにまとめる。

`session` には、その一覧を持つセッションの ID の先頭8桁を含む文字列を入れる(例: `session-0f692c4e`)。帯と `/board` には、現在のセッションの ID の先頭8桁を `session` に含む一覧と、`session` の無い手書きの一覧(全セッション共通)だけを出す。

- 別のセッションの `session` を持つ一覧は出さない。新しく開いたセッションには、前のセッションの一覧は出ない。
- 現在のセッションに一致する一覧が1つでもあれば、`/board` の見出しに「このセッションの一覧だけ表示中」と出る。
- サイドカーが書く `auto` 系の一覧(`auto.<ID先頭8桁>.json`)は、`session` が一致するときだけ出す。`session` の無い `auto.json` は、どのセッションのものか分からないので出さない。
- 現在のセッションの ID は `$.session.id()` を3秒ごとの読み直しのたびに取る。`/clear` で ID が変わると、次の読み直しで絞り込み先も変わる。

```json
{
  "updated_at": "2026-10-04T22:00+09:00",
  "session": "session-0f692c4e",
  "tasks": [
    { "id": "T1", "title": "短いタイトル", "status": "implementing", "ws": "w2" },
    { "id": "T2", "title": "別のタイトル", "status": "waiting (T1後)", "ws": null }
  ]
}
```

`status` の先頭の語で分類する。

| 先頭の語 | 分類 |
| :- | :- |
| `implementing` / `fixing` / `running` | 進行中 |
| `merged` / `done` | 完了 |
| それ以外(`waiting` / `queued` など) | 未着手 |

1行目はタイトルだけを出す。先頭の語より後ろ(例: `(T1後)` は括弧を外して `T1後`)と `ws` は、`/board` の Pane では2行目にインデントして薄字で出す。帯はタイトルだけで、補足は出さない。

ファイルは Claude に書かせる。CLAUDE.md には、たとえば次のように書く。

```markdown
作業の割り振りが変わったら `.claude/tasks/<名前>.json` を更新する(形式は task-board の README)。
```

## サイドカー(自動更新)

`.claude/tasks/` があるプロジェクトでは、メインの回答が終わるたびに `$.model.fork` で会話を読み、タスクの status を実態へ寄せる。メインと同じモデル・同じ履歴を使い、メインのターンの終了は待たせない。呼び出しは30秒に1回まで。間隔内に終わった回答は捨てず(最大8件・各8000字、古い順)、間隔が空いた後の次の読み直し(3秒ごと)でまとめて処理する。待機中に /cd や /clear で別の repo・別の会話へ移ったら溜めた回答は破棄し、保存は処理開始時の repo の絶対パスへ行う。

現在のセッションの手書き一覧(`session` の無い共通の一覧を含む)があるときは、手書きの JSON を書き換えず、変更提案を `.claude/task-board/overlay/<ハッシュ>.json`(ハッシュは一覧名と id から作る。中身に一覧名と id を持つ) へ1タスク1ファイルで保存し、画面だけ重ねる。

- 帯・`/board` の行には `auto(推定) JSON: <手書きの値>` が付く。`/board` の下部に判定時刻と根拠(回答からの引用。重ねた全行ぶん)が出る。根拠は検証済みの事実ではなく、推定の手がかり。
- 完了にするのは、回答で完了が明示されたときだけ。着手(implementing)も、着手や起動が明示されたときだけ。
- 画面の値が誤りだと回答で訂正すれば、提案は手書きの値へ戻り、重ねた表示が消える。
- 手書きの status を人が書き換えると、重ねた表示は無効になる。
- mod 側で提案を検証し、実在しない一覧・id、既知の語でない status、回答に無い引用、対象タスクの id を単独で名指ししない引用(`T5` は「T53」に一致しない)、1回11件以上の変更は捨てる。title と ws は変えない。
- 現在のセッションの手書き一覧があれば、サイドカーの一覧は表示しない。

現在のセッションの手書き一覧が無いときは、会話から一覧そのものを `.claude/tasks/auto.<ID先頭8桁>.json` に書く(セッションごとに別ファイル)。

- `.claude/tasks/` が無いプロジェクトでは動かない(全プロジェクトにファイルを作らないため)。
- 変更が無い・返答が読めない・ファイルが壊れているときは何も書かない。
- ターンごとに fork を1回呼ぶので、その分のトークンを使う。止めるには `.claude/tasks/` を消す。

## 使い方

```sh
claude --plugin-dir <このフォルダ>
```

## 検証

```sh
npx -y -p typescript tsc -p .   # 型チェック
claude plugin validate .        # 構文
claude plugin test .            # tests/*.test.ts(status の分類と補足、overlay の検証と適用)
```

## 制約

- 帯の高さにはエンジン側の上限がある。畳んだ表示は未完了の上位5件に限り、全件は `/board` の Pane で見る。
- `ctrl+t` による表示・非表示の切り替えには対応していない。帯を隠すにはエンジン標準の `[-]` を使う。
