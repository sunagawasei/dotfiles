# /autorun

引数の依頼を、途中で判断を仰がずにcommitとwrapupまで通す。

## 手順

1. **引数を依頼として受け取る。** 引数が空なら直前のやり取りで扱っていたタスクを対象にする。対象が特定できないときだけ聞く
2. **調査して原因と方針を決める。** 設計の選択肢をユーザーへ出して待たない。分かれ道は自分で選び、選んだ理由は最終報告へ書く
3. **実装し、実測で検証する。** ベースラインで不具合を再現してから直す。「動くはず」で終えない
4. **検収する。** 実物（`git diff` / `git log` / test）を自分で確認する。ここは省略しない
5. **commitする。** pushはしない
6. **`wrapup` skillを既定モード（引数なし）で通す**
7. **最終報告を1通で出す。** 結論 → やったこと → ユーザーが次にやること → やり残し、の順

## 手を止めてユーザーに聞く場合

次の4つだけ。それ以外の判断は全部こちらで決める。

- **不可逆・破壊的な操作。** リソースやファイルの削除、force push、履歴の書き換え。ただしこのセッションで自分が作ったファイルの片付けは聞かずに消してよい（消す前に対象を1件ずつ見て、自分が作ったものだけに絞る）
- **外部へ出る操作。** GitHub Issue/PR/commentの作成・変更、外部サービスへのアップロード・送信
- **クラウドリソースの操作。** AWS等はコマンドを提示するだけで実行しない
- **依頼が成り立たないと分かったとき。** 対象が存在しない、前提が矛盾している、実行不能

## 効く規約・効かない規約

- グローバルCLAUDE.mdの委譲フロー・安全規約・出力規約はそのまま効く
- **免除されるのは段4のユーザー承認だけ。** この依頼自体が事前承認にあたる。査読ゲート（段2・段3・段9）と検収（段11）は残る
- `~/.config` 配下の作業では重い査読ゲートを掛けない（段2・段3・段9の反復は過剰）
- このskillはStopフックを張らない。途中で止まらないことを強制したいなら `/goal` を併用する
