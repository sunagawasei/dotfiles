# セッションの収穫（学びの還元と総点検）

セッションを閉じる前に実行し、Claude Code運用の効率化資産（skill/rule/メモリ/CLAUDE.md）を更新する。

## モード

- **既定（引数なし、または`auto`）**: 段4の採否も段6の対応要否確認も取らず、追加・更新・削除をすべて適用してcommitまで進める。段6は未実施リストを報告して終わる
- **confirm（ARGUMENTSが`confirm`）**: 段4で候補一覧の採否を取り、削除は1件ずつ採否を取る。段6でやり残しの対応要否を確認する
- `auto`・`confirm`以外の引数が渡されたら、認識できない引数である旨を1行告げて既定モードで動く

安全弁はモードによらず共通で効かせる — 「迷ったら残して報告する」（段3）、メモリは`rm`せずattic退避（段5）、退避前後の`[[link]]`の組の照合（段5）、手に余る規模なら`claude-audit`を呼ぶ（段5）。

**削除方針**: 件数・容量の削減自体を目標にしない。古い・矛盾する・チーム決定(や既存資産)と混同された記述を見つけたら、その都度積極的に消す（陳腐化ベース）。

## ワークフロー

### 1. セッションの振り返り

- このセッションでの (a)ユーザーの訂正・ダメ出し（特に2回以上繰り返されたもの） (b)毎回説明し直した前提知識 (c)繰り返した多段手順 (d)新しく確立した運用・好み (e)非自明な技術的発見（ハマりどころ・制約） (f)返答の形式・トーン・構成についてユーザーが述べた個人的な好み（例: 結論を先に／簡潔に／見出しを使わない／確認の頻度・口調等。コード規約ではなく応答スタイルそのものへの指摘） (g)このセッションで無効化された既存資産 を洗い出す
- (g)のトリガーは以下の5種:
  - ユーザーが「もうそれはしない」「それは違った」と述べ、既存メモリ/ruleがそれを記述している
  - 資産が参照しているファイル・コマンド・skillをこのセッションで削除・改名した
  - projectメモリの「未コミット」「〜予定」「作業中」の記述がこのセッションで完了した
  - 段1(a)〜(f)の新候補が既存資産を置き換える
  - **本セッションの作業（grep・参照確認等）で偶然目に入った既存メモリが陳腐化している**: 一時的な事情の記述に解除条件・時期が無い、内容が今の状態と食い違う、個人の記録がチームの決定・既存資産の記述と混同されている、のいずれか。全件の意図的な総ざらいはしない（それは`claude-audit`の役割） — 気づいたものだけを積極的に候補に挙げる
- メモリのtype別の削除根拠: feedback/userはユーザーの撤回発言で足りる。projectは完了の確認で足りる。**referenceだけは参照先の消滅・変更を実物で確認したものに限る**（伝聞・推測では削除しない）

### 2. 還元先の分類（公式の使い分け基準）

- **skill**: 繰り返した多段手順・30行超のワークフロー（/skill-nameで呼ぶもの）。**スコープ判断**: そのプロジェクト固有の手順は`<project>/.claude/skills/`（プロジェクトローカル）、複数プロジェクトで再利用する汎用手順は`claude/skills/`（グローバル）
- **rule**（.claude/rules/ or claude/rules/）: 特定ファイル種別・作業種別への一貫した規約（pathsで自動適用）。同様にプロジェクト固有かグローバル共通かで置き場所を分ける
- **メモリ**: feedback（ユーザーの指示・訂正+Why/How） / project（進行状況・非自明な制約） / reference（外部情報・環境事実） / user（好み・背景）。1事実1ファイル+MEMORY.mdインデックス。**スコープ判断**: auto memoryは作業ディレクトリ（プロジェクト）ごとに保存領域が分かれる。プロジェクト固有の実装・業務に閉じる学びはそのプロジェクトで作業中のセッションのメモリに置くのを基本とする（本セッション=`~/.config`にはClaude Code運用や複数プロジェクト共通の知見を保存する）
- **CLAUDE.md**: 毎セッション必要な事実・規約のみ（グローバル=全プロジェクト共通の好み、プロジェクト=そのリポジトリの前提）。200行制限に注意
- **hook/設定（settings.json）**: 「毎回確実に」実行/禁止したいもの、環境変数、パーミッション設定（CLAUDE.mdは強制ではない）。グローバル（`~/.claude/settings.json`）かプロジェクトローカル（`<project>/.claude/settings.json`）かは適用範囲で判断（詳細は`update-config` skill参照）
- **削除 / 統合 / 参照化**: 段1(g)で洗い出した無効化資産の行き先。単純に削除するだけでなく、有効な部分だけ既存資産へ統合する・別資産からの参照に置き換える、のいずれかを候補ごとに選ぶ
- **グローバルへの昇格チェック（プロジェクトローカルとグローバルは排他ではない）**: 候補をプロジェクトローカルに分類した場合でも、そこから複数プロジェクトに敷衍できる一般則（Claude Code運用そのもの・ツールの癖・環境制約等）を抽出できるなら、その汎用部分だけを抽象化してグローバルメモリまたはグローバル`claude/CLAUDE.md`にも合わせて反映すべきか検討する。プロジェクト固有の実装詳細（固有名詞・具体的な設定値等）はプロジェクト側に残し、汎用部分だけを切り出す
- **(f)の返答スタイルの好みは既定でグローバル扱い**: プロジェクト固有の作業内容ではなく応答の作り方そのものなので、原則グローバル（`claude/CLAUDE.md`の出力規約・対話規約 or グローバルfeedbackメモリ）に振り分ける。プロジェクト限定と明言された場合のみそのプロジェクトのCLAUDE.md/メモリに留める

### 3. 既存資産との突き合わせ

- 候補ごとに既存のskill/rule/メモリ/CLAUDE.mdをgrepし、既にあれば「更新」、なければ「新規」に振り分け。重複を作らない
- スコープ判断を伴う候補（skill/rule/メモリ/設定）は、対象プロジェクト側とグローバル（`~/.config`）側の両方を確認し、同じ内容を両スコープに重複して置かない
- (f)の候補は特にグローバルCLAUDE.mdの「出力規約」「対話・確認の規約」セクションと突き合わせ、既存文言の微調整で吸収できないか優先確認する
- **削除候補の逆引き確認**: 主の逆引きは (a) MEMORY.mdのインデックス行 (b) CLAUDE.md・skill・ruleからの名前/パス参照。加えて全プロジェクトのメモリを`grep -rl <name> ~/.config/claude/projects/*/memory`で走査する（全プロジェクト分でも一瞬で終わる）。`[[link]]`はグローバルメモリdirに未解決が多数あるため「指している側が無い=安全」の判定には使えない。**削除の前後で「新たに未解決になった組」が出ていないかの確認にだけ使う**（段5の`pairs`）
- 安全基準: 削除は「repoに記録済み/統合済み/明確に陳腐化」のいずれかに該当するもののみ。迷ったら残して報告する

### 4. ユーザー確認

- 候補一覧（還元先・スコープ〔プロジェクトローカル/グローバル〕・新規/更新/削除・一行要約）を提示する
- **既定では採否を取らない**。候補一覧を提示したうえで、確認を待たず段5へ進む（削除も1件ずつの採否を取らない）
- **confirmモードでのみ採否を取る**。そのとき削除は1件ずつ採否を取る（追加とまとめて一括承認しない）
- **削除候補が6件以上なら、削除分は候補一覧に記録するだけにして段5で`claude-audit`へ回す**（このセッション起因の範囲を超えているシグナルのため）

### 5. 適用

- 承認分をsonnetサブエージェント（model: sonnet）に委譲して適用（メインは検証）。dotfilesの変更はユーザー承認後にcommitエージェントでコミット
- **削除の後始末はwrapup自身が行う**（`claude-audit`はグローバルskillなのでどのプロジェクトからも呼べるが、呼ぶのは下記の3条件に該当したときだけ。通常の後始末を丸投げしない）:
  - git追跡ファイル（skill/rule/CLAUDE.md）→ `git rm`。履歴から戻せる
  - git非追跡ファイル（`~/.config/claude/projects/*/memory/`のメモリは全件がこれ）→ `rm`せず`~/.config/claude/attic/<YYYY-MM-DD>/<元の相対パス>`へ退避する。`claude/*`が.gitignore対象なのでallowlist追加は不要。**パスは絶対で書く** — このskillは`~/.config`以外のプロジェクトのセッションからも走るため、相対パスは解決しない
  - MEMORY.mdのインデックス行を削除する
  - 退避前後で`[[link]]`の**組**（参照元ファイル, 対象名）を採り、**退避後にだけ現れる組が無い**ことを確認する。件数の一致では判定しない（既存の未解決1件を直して別の1件を増やしても件数は揃う）。減るのは正常なので増加側だけを見る:

    ```bash
    cd <memory dir>; W=<scratchpad>/links.$$
    pairs() { for f in *.md; do grep -o '\[\[[A-Za-z0-9_-]*\]\]' "$f" | tr -d '[]' | while read n; do [ -f "$n.md" ] || echo "$f|$n"; done; done | sort -u; }
    pairs > $W.before   # 退避前
    # …退避…
    pairs > $W.after; comm -13 $W.before $W.after   # 空であること
    ```

  - **増えた組が出たら参照元を張り替える**（退避したメモリを指していたリンクが宙に浮いた状態）。参照元ファイルごとに: 統合先メモリがあれば`[[統合先]]`へ置換、無ければリンク記法だけ外して本文は残す。置換後に`pairs`を採り直し、`comm -13`が空になるまで繰り返す（実例: 2026-09-14に7件を退避して未解決が12→17へ増え、参照元8ファイルを張り替えて12へ戻した）
- **適用後にMEMORY.mdの索引を全件照合する**。メモリの保存は「ファイル作成」と「索引追加」の2手に分かれており、片方だけ成功しても静かに通る。索引に無いファイルはrecallで拾われないため、書いた本人以外からは存在しないのと同じになる（実例: 2026-07-08の1セッションが4件を書いて索引追加を丸ごと飛ばし、2026-09-14のwrapupで件数を突き合わせるまで2か月気づかなかった）。このセッションが作ったものに限らず**dir全体**を対象にする。索引に無いファイルが見つかったら1行要約を書いて追加し、索引にあって実体が無い行は削除する:

  ```bash
  cd <memory dir>
  for f in *.md; do [ "$f" = MEMORY.md ] && continue
    grep -qxF "$f" ARCHIVED 2>/dev/null && continue
    grep -q "($f)" MEMORY.md || echo "NOT INDEXED: $f"; done
  grep -o '^- \[[^]]*\](\([^)]*\))' MEMORY.md | sed 's/.*(\(.*\))/\1/' | while read n; do [ -f "$n" ] || echo "DANGLING: $n"; done
  wc -l MEMORY.md; wc -c MEMORY.md   # 200行・25600バイトが上限
  ```

- **索引の上限に達しているdirでは、NOT INDEXEDを漏れと断定しない**。MEMORY.mdは先頭200行または25KBの早い方までしかロードされず、超過分は黙って捨てられる。そのため索引が上限に近いdirでは、入りきらないメモリを**意図的に**索引から外していることがある（実例: 2026-09-14、containerregistryで47項目を意図的に外しており、翌日のwrapupがそれを46件の漏れとして報告した）。見分け方:
  - **`ARCHIVED`（拡張子なし・1行1ファイル名）に載っていれば意図的**。上のスクリプトはこれをスキップする。意図的に索引から外したら、同時にこのファイルへ1行足す
  - `ARCHIVED`が無く、かつMEMORY.mdが上限近傍（180行以上または23000バイト以上）なら、漏れと断定せず件数だけ報告して段6の未実施リストへ「`ARCHIVED`未整備のため未判定N件。整備するまでこのdirでは本物の索引漏れも同じ数に紛れて検出されない」と載せる
  - `ARCHIVED`が抑止できるのは**実在ファイルのNOT INDEXEDだけ**。DANGLING・重複・未解決リンクは`ARCHIVED`に書かれていても通常どおり報告する
- 索引へ行を足すときは`wc -l` < 200 かつ `wc -c` < 25600 の両方を確認する。超えるなら行を増やさず既存行へ統合する
- **`claude-audit`を呼ぶ条件**（いずれか1つ該当。既定モードでは呼ぶかどうかの確認をユーザーに取らない）:
  - 段4の削除候補が6件以上
  - NOT INDEXED/DANGLINGが合計6件以上。ただし`ARCHIVED`登録分と上記の「未判定」分は数に入れない（入れると、意図的な索引外しがあるdirで毎回起動して同じ報告が返る）
  - 上の張り替えをしても`comm -13`が空にならない
- **呼び方**: 上の照合まで終えてから、Skill toolで`claude-audit`を`memory <対象memory dirの絶対パス>`付きで起動する（confirmモードなら末尾に`--confirm`）。返る区分は`修正した / attic退避した / 未対応 / invalid target`で、`未対応`は段6の未実施リストへ載せる
  - Skill toolから起動できなかった場合（toolが無い・skill名が解決できない・起動時エラーで**変更が1件も入っていない**）は、`claude/skills/claude-audit/SKILL.md`を読んで`memory`モードの手順をその場で実行する
  - 起動はしたが結果区分が返らず、変更が入った**または入ったか分からない**場合は**その場の再実行をしない**。二重適用になるため、段6へ「claude-audit途中終了・要手動確認」として載せる（変更ゼロを積極的に確認できないときはこちらに倒す）
- **`claude-audit`から戻ったら、上の索引照合・`pairs`の照合・`wc -l`/`wc -c`をもう一度通してから段6へ進む**。auditがMEMORY.mdやリンクを変えているため、呼ぶ前の確認結果は無効になっている。**再検証が通らなければcommitへ進まず、そこで止めてユーザーへ報告する**

### 6. やり残し総点検

- セッション内の「あとで対応」「必要なら実施します」等の約束・提案・保留、サブエージェント報告の「未対応の提案」「スコープ外」項目を洗い出し、未実施リストを提示する。**既定では対応要否を問わず、未実施リストを報告して終わる。confirmモードでのみ対応要否を確認する**
- **セッション中に解決済み・不要になった保留項目は未実施リストから落とす**が、落とした事実は一覧に残し、**「どのcommitで/どの返信で解決したか」を1語添える**（ユーザーが漏れと意図的な除外を区別できるように）。「解決済み」のような抽象語で済ませない

## 関連

- 常時規約: 同チェックはタスク完了時にも都度行う（グローバルCLAUDE.md「対話・確認の規約」）
- 定期棚卸し（資産全体を意図的に総ざらいする重複・矛盾・陳腐化の掃除）は`/claude-audit`（こちらは蓄積後の掃除で全件を走査する）。wrapupは都度の還元で、削除も**このセッションが無効にしたもの、または作業中に偶然気づいた陳腐化**を対象とする — 全件の意図的な洗い出しはclaude-audit側の役割のまま変えない
