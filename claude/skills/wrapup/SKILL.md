# セッションの収穫（学びの還元と総点検）

セッションを閉じる前に実行する。このセッションで暗黙のまま使われた知識(言葉にされていない好み・判断・手順・環境の癖)を形式知に変え、Claude Code運用の効率化資産（skill/rule/メモリ/CLAUDE.md）を更新する。形式知になっていないものは、次のセッションのエージェントには存在しない。

## モード

既定（引数なし、または`auto`）と`confirm`（ARGUMENTSが`confirm`）の違いはこの表だけに書く。各段は表に従う。

| 場面 | 既定 | `confirm` |
|---|---|---|
| 段4 候補一覧 | 提示し、確認を待たず段5へ進む | 採否を取る |
| 段4 削除 | 1件ずつの採否を取らない | 1件ずつ採否を取る（追加と一括承認しない） |
| 段5 適用 | 追加・更新・削除をすべて適用し、commitまで進める | 段4で承認された範囲だけ適用し、commitする |
| 段5 `claude-audit`の起動 | 呼ぶかどうかの確認を取らずに呼ぶ | `--confirm`を付けて起動し、採否はaudit側で取る |
| 段6 やり残し | 未実施リストを報告して終わる | 対応要否を確認する |

- 引数なし以外で`auto`・`confirm`のどちらでもない引数(`confrim`等の誤記を含む)が渡されたら、何も変更せず止まり、認識できない引数と使える引数(`auto`/`confirm`)を1行で告げる。誤記のまま既定モードで動くと、確認のつもりが削除まで承認なしで適用される

安全弁はモードによらず共通で効かせる — 「迷ったら残して報告する」（段3）、メモリは`rm`せずattic退避（段5）、退避前後の`[[link]]`の組の照合（段5）、手に余る規模なら`claude-audit`を呼ぶ（段5）。

**削除方針**: メモリは少ないほどよい(MEMORY.mdは先頭200行/25KBを超えた分が読み込まれず、CLAUDE.mdは短いほど従われる)。古い・矛盾する・重複する・チーム決定(や既存資産)と混同された記述を見つけたら、その都度積極的に消す・統合する。索引が上限に近づいたら、このセッション起因でなくても`claude-audit`で整理する(段5)。

## ワークフロー

### 1. セッションの振り返り

- **入力はこのセッションでユーザーが発した発言の全件**。記憶や直前の会話だけで振り返らない — `/clear`や自動圧縮の後は前半の発言が文脈から落ちている。次で全文を取る(現在セッションは切り詰めない):

  ```bash
  wrapup-recall current
  ```

  - 発言を1件ずつ読み、「訂正 / 指示 / 質問 / 好みの表明」のどれかを判断する。形式知にする価値があるものだけを下の(a)〜(g)の候補にする。質問と単発の指示は候補にしない
  - 終了コードで分ける。**どの場合も、取得できなかったことを「候補なし」として扱わない**。0以外では文脈に残る発言だけで進め、報告の冒頭に下の文言を書く:

  | 終了コード | 意味 | 報告の冒頭に書く文言 |
  |---|---|---|
  | 0 | 取得できた | （なし。出力を読む） |
  | 3 | `recall`が未導入 | 「recall未導入: 文脈に残る発言のみ」 |
  | 4 | `recall`の取得に失敗（import/export失敗・出力不正・現在セッションの発言が0件） | 「取得失敗: stderrの1行」 |
  | 5 | `$CLAUDE_CODE_SESSION_ID`が空 | 「セッションID不明: 文脈に残る発言のみ」 |
  | 2 | `wrapup-recall`の引数の誤り（このskillの書き間違い） | 「wrapup-recallの呼び出し誤り: stderrの1行」 |

  - `command -v wrapup-recall`が通らないときは未配備として「wrapup-recall未配備: 文脈に残る発言のみ」と書く。配備は`cd ~/.config/scripts && go build -o ~/.local/bin/wrapup-recall ./cmd/wrapup-recall`
- 発言から (a)ユーザーの訂正・ダメ出し（特に2回以上繰り返されたもの） (b)毎回説明し直した前提知識 (c)繰り返した多段手順 (d)タスクの進め方の好み・運用（確認を取る頻度・タスクの分割単位・順序・承認の取り方・委譲のさせ方など、何を作るかでなくどう進めるか） (e)非自明な技術的発見（ハマりどころ・制約） (f)返答の形式・トーン・構成についてユーザーが述べた個人的な好み（例: 結論を先に／簡潔に／見出しを使わない／口調等。コード規約ではなく応答スタイルそのものへの指摘） (g)このセッションで無効化された既存資産 (h)(a)〜(g)のどれにも当てはまらなくても、エージェントを使う中で形式知にすれば次回以降の手戻りや説明し直しを防げるもの全般（例: 委譲先・モデルの使い分け、承認プロンプトが繰り返し出た操作、ツール・環境の癖、よく頼む作業の型、ユーザーの役割・背景、外部資源の所在） を洗い出す。(a)〜(h)は分類の例示で、候補の上限ではない。出どころは発言だけでなく、自分の失敗・ツールのエラー・手戻りも見る。ユーザーが言葉にせず選んだこと(繰り返し選んだ選択肢・承認や拒否・中断・黙って受け入れた提案や、直さずに通した出力)も見る。言葉にされていない好みは推測で断定せず、根拠にした場面を添えて候補にする。判断基準は「次のセッションで同じ手戻りを防ぐか」で、コードやrepoから導出できるものは候補にしない。各候補は段2でグローバル/プロジェクトと還元先の種別を決める
- (g)のトリガーは以下の5種:
  - ユーザーが「もうそれはしない」「それは違った」と述べ、既存メモリ/ruleがそれを記述している
  - 資産が参照しているファイル・コマンド・skillをこのセッションで削除・改名した
  - projectメモリの「未コミット」「〜予定」「作業中」の記述がこのセッションで完了した
  - 段1(a)〜(f)の新候補が既存資産を置き換える
  - **本セッションの作業（grep・参照確認等）で偶然目に入った既存メモリが陳腐化している**: 一時的な事情の記述に解除条件・時期が無い、内容が今の状態と食い違う、個人の記録がチームの決定・既存資産の記述と混同されている、のいずれか。全件の意図的な総ざらいはしない（それは`claude-audit`の役割） — 気づいたものだけを積極的に候補に挙げる
- メモリのtype別の削除根拠: feedback/userはユーザーの撤回発言で足りる。projectは完了の確認で足りる。**referenceだけは参照先の消滅・変更を実物で確認したものに限る**（伝聞・推測では削除しない）
- **このセッションで繰り返された訂正が、既存のskill/rule/メモリ/CLAUDE.mdに既に書いてあるなら、文言の追記ではなく「その資産が効いていない」を候補にする**。処方は (i)読まれる場所へ移す(メモリ→CLAUDE.md) (ii)hookで強制する (iii)抽象的な禁止を具体的な場面の書き方に改める、のどれかを選び、harnessの修正案として段4に出す
- 訂正をキーワード(「違う」「不要」等)のgrepで探さない。キーワードに当たる発話の大半は質問・指示で、訂正はごく一部になる。発話を読んで判断する
- 対象は**このセッションの発言だけ**。wrapupは毎回実行するので、過去のセッションは読まない

### 2. 還元先の分類（公式の使い分け基準）

- **skill**: 繰り返した多段手順・30行超のワークフロー（/skill-nameで呼ぶもの）。**スコープ判断**: そのプロジェクト固有の手順は`<project>/.claude/skills/`（プロジェクトローカル）、複数プロジェクトで再利用する汎用手順は`claude/skills/`（グローバル）
- **rule**（.claude/rules/ or claude/rules/）: 特定ファイル種別・作業種別への一貫した規約（pathsで自動適用）。同様にプロジェクト固有かグローバル共通かで置き場所を分ける
- **メモリ**: feedback（ユーザーの指示・訂正+Why/How） / project（進行状況・非自明な制約） / reference（外部情報・環境事実） / user（好み・背景）。1事実1ファイル+MEMORY.mdインデックス。**スコープ判断**: auto memoryは作業ディレクトリ（プロジェクト）ごとに保存領域が分かれる。プロジェクト固有の実装・業務に閉じる学びはそのプロジェクトで作業中のセッションのメモリに置くのを基本とする（本セッション=`~/.config`にはClaude Code運用や複数プロジェクト共通の知見を保存する）
- **CLAUDE.md**: 毎セッション必要な事実・規約のみ（グローバル=全プロジェクト共通の好み、プロジェクト=そのリポジトリの前提）。200行制限に注意
- **hook/設定（settings.json）**: 「毎回確実に」実行/禁止したいもの、環境変数、パーミッション設定（CLAUDE.mdは強制ではない）。グローバル（`~/.claude/settings.json`）かプロジェクトローカル（`<project>/.claude/settings.json`）かは適用範囲で判断（詳細は`update-config` skill参照）
- **上のどれにも収まらない形式知は、置き場そのものを提案する**: 例はagent定義（`claude/agents/`）、docs、権限のallow、繰り返す作業のGo製CLI。候補一覧では「新しい置き場」と印を付ける。既存の置き場に無理に押し込まない
- **削除 / 統合 / 参照化**: 段1(g)で洗い出した無効化資産の行き先。単純に削除するだけでなく、有効な部分だけ既存資産へ統合する・別資産からの参照に置き換える、のいずれかを候補ごとに選ぶ
- **グローバルへの昇格チェック（プロジェクトローカルとグローバルは排他ではない）**: 候補をプロジェクトローカルに分類した場合でも、そこから複数プロジェクトに敷衍できる一般則（Claude Code運用そのもの・ツールの癖・環境制約等）を抽出できるなら、その汎用部分だけを抽象化してグローバルメモリまたはグローバル`claude/CLAUDE.md`にも合わせて反映すべきか検討する。プロジェクト固有の実装詳細（固有名詞・具体的な設定値等）はプロジェクト側に残し、汎用部分だけを切り出す
- **(f)の返答スタイルの好みと(d)のタスクの進め方の好みは既定でグローバル扱い**: プロジェクト固有の作業内容ではなく応答・進行の作り方そのものなので、原則グローバル（`claude/CLAUDE.md`の出力規約・対話規約 or グローバルfeedbackメモリ）に振り分ける。プロジェクト限定と明言された場合のみそのプロジェクトのCLAUDE.md/メモリに留める

### 3. 既存資産との突き合わせ

- 候補ごとに既存のskill/rule/メモリ/CLAUDE.mdをgrepし、既にあれば「更新」、なければ「新規」に振り分け。重複を作らない
- スコープ判断を伴う候補（skill/rule/メモリ/設定）は、対象プロジェクト側とグローバル（`~/.config`）側の両方を確認し、同じ内容を両スコープに重複して置かない
- (f)の候補は特にグローバルCLAUDE.mdの「出力規約」「対話・確認の規約」セクションと突き合わせ、既存文言の微調整で吸収できないか優先確認する
- **削除候補の逆引き確認**: 主の逆引きは (a) MEMORY.mdのインデックス行 (b) CLAUDE.md・skill・ruleからの名前/パス参照。加えて全プロジェクトのメモリを`grep -rl <name> ~/.config/claude/projects/*/memory`で走査する（全プロジェクト分でも一瞬で終わる）。`[[link]]`はグローバルメモリdirに未解決が多数あるため「指している側が無い=安全」の判定には使えない。**削除の前後で「新たに未解決になった組」が出ていないかの確認にだけ使う**（段5の`pairs`）。**逆引きで見つけた参照は、削除前に1件ずつ「参照元を更新した」か「削除を見送った」のどちらかで解消する**。`[[link]]`以外の参照（名前・絶対パス・通常のMarkdownリンク。他プロジェクトのメモリからのものを含む）は`pairs`に出ないので、検査が通っても残る。削除後に同じ`grep`をもう一度かけ、退避したメモリを指す参照が0件であることを確認する
- 安全基準: 削除は「repoに記録済み/統合済み/明確に陳腐化」のいずれかに該当するもののみ。迷ったら残して報告する

### 4. ユーザー確認

- 候補一覧（還元先・スコープ〔プロジェクトローカル/グローバル〕・新規/更新/削除・一行要約）を提示する。段1で「既存資産が効いていない」と分かったものはその印を添える
- 採否の取り方はモード表に従う
- **メモリの削除候補が3件以上で、対象のmemory dirがあるなら、そのメモリ削除分は候補一覧に記録するだけにして段5で`claude-audit`へ回す**（このセッション起因の範囲を超えているシグナルのため）。`claude-audit`の`memory`モードはmemory dirしか扱えないので、skill/rule/CLAUDE.mdの削除候補は件数にかかわらず回さない。それらは段5でwrapup自身が`git rm`で適用する。3件以上あるときは、段6の未実施リストへ「skill/rule/CLAUDE.mdの棚卸しは`/claude-audit`（引数なし）で」と載せる

### 5. 適用

- メインセッションで採用した変更を適用し、差分と必要な検証を確認してcommitする。適用する範囲はモード表に従う。
- **削除の後始末はwrapup自身が行う**（`claude-audit`はグローバルskillなのでどのプロジェクトからも呼べるが、呼ぶのは下記の3条件に該当したときだけ。通常の後始末を丸投げしない）:
  - git追跡ファイル（skill/rule/CLAUDE.md）→ `git rm`。履歴から戻せる
  - git非追跡ファイル（`~/.config/claude/projects/*/memory/`のメモリは全件がこれ）→ `rm`せず`~/.config/claude/attic/<YYYY-MM-DD>/<元の相対パス>`へ退避する。`claude/*`が.gitignore対象なのでallowlist追加は不要。**パスは絶対で書く** — このskillは`~/.config`以外のプロジェクトのセッションからも走るため、相対パスは解決しない
  - MEMORY.mdのインデックス行を削除する
  - 退避前後で未解決の`[[link]]`の**組**（参照元ファイル, 対象名）を採り、**退避後にだけ現れる組が無い**ことを確認する。件数の一致では判定しない（既存の未解決1件を直して別の1件を増やしても件数は揃う）。減るのは正常なので増加側だけを見る:

    ```bash
    W=<scratchpad>/links.$$
    memcheck pairs <memory dir> > $W.before || echo "検査不能: 退避しない"   # 退避前
    # …退避…
    memcheck pairs <memory dir> > $W.after && comm -13 $W.before $W.after || echo "検査不能"   # 空であること
    ```

    **`memcheck pairs`の終了コードが0でない出力は、空でも「増えた組なし」と読まない**。退避前の取得が失敗したら退避に進まない。退避後の取得が失敗したら、削除を終えたまま`commit`へ進まず、終了報告を「中断」にする

  - **増えた組が出たら参照元を張り替える**（退避したメモリを指していたリンクが宙に浮いた状態）。参照元ファイルごとに: 統合先メモリがあれば`[[統合先]]`へ置換、無ければリンク記法だけ外して本文は残す。置換後に`memcheck pairs`を採り直し、`comm -13`が空になるまで繰り返す
- **適用後にMEMORY.mdの索引を`memcheck check`で全件照合する**。メモリの保存は「ファイル作成」と「索引追加」の2手に分かれており、片方だけ成功しても静かに通る。索引に無いファイルはrecallで拾われないため、書いた本人以外からは存在しないのと同じになる。このセッションが作ったものに限らず**dir全体**を対象にする。判定規則はすべて`memcheck`に実装してあり、`claude-audit`も同じものを呼ぶ:

  ```bash
  memcheck check <memory dir>
  ```

  - **終了コードで分ける**。0は要対応なし、1は下の行を読んで対応する。**3（対象が不正）と4（読取失敗）は照合できていない**。「索引は問題なし」とは扱わず、`claude-audit`も呼ばず、段6へ「memcheck検査不能: stderrの1行」と載せる。`command -v memcheck`が通らないときも同じ。**このセッションでメモリを削除・退避していたときは、削除後のリンク安全性を確認できていないので、`commit`へ進まず終了報告を「中断」にする**。配備は`cd ~/.config/scripts && go build -o ~/.local/bin/memcheck ./cmd/memcheck`
  - `NOT_INDEXED <file>`: 1行要約を書いて索引へ追加する
  - `DANGLING <file>`・`DUPLICATE <file>`: 実体が無い行は削除し、重複行は1行に統合する
  - `NEAR_LIMIT`・`OVER_LIMIT`: 行を足さず既存行へ統合する。MEMORY.mdは先頭200行または25600バイトを超えた分が黙って捨てられる
  - `UNDECIDED N`: 索引が上限近傍で`ARCHIVED`も無く、入りきらないメモリを意図的に外したのか漏れなのか区別できない。漏れと断定せず、段6へ「`ARCHIVED`未整備のため未判定N件。整備するまでこのdirでは本物の索引漏れも同じ数に紛れて検出されない」と載せる
  - `UNRESOLVED <file>|<name>`: 既存の未解決リンク。情報であって対応は要らない。増えたかどうかは上の`memcheck pairs`の前後比較で見る
  - **`ARCHIVED`**（拡張子なし・1行1ファイル名）は、索引から**意図的に**外したメモリの一覧。意図的に外したら、同時にこのファイルへ1行足す。`ARCHIVED`が抑止するのは実在ファイルの`NOT_INDEXED`だけで、`DANGLING`・`DUPLICATE`・未解決リンクは載っていても通常どおり出る
- 索引へ行を足したあとに`memcheck check`をもう一度かけ、`NEAR_LIMIT`・`OVER_LIMIT`が出ないことを確認する
- **索引を縮めるときは行を消さず、説明(` — `以降)を短くするか落とす**。タイトルとリンクは残す。次の3点を守る:
  - 文字数での機械的な切り詰めは使わない。「09-29」のような途中で切れた断片が残るため、手で書き直す
  - 説明に埋まった`(xxx.md)`の参照は落とさない。そのメモリへの唯一の入口のことがある
  - 適用前後でリンク先ファイル名の集合が一致することを確認する: `diff <(grep -o '([A-Za-z0-9_.-]*\.md)' 旧 | sort) <(grep -o '([A-Za-z0-9_.-]*\.md)' 新 | sort)`
- **`claude-audit`を呼ぶ条件**（いずれか1つ該当）:
  - 段4のメモリ削除候補が3件以上（対象memory dirがあるとき）
  - `memcheck check`が終了コード1を返した（`NOT_INDEXED`・`DANGLING`・`DUPLICATE`・`NEAR_LIMIT`・`OVER_LIMIT`のいずれか）。**`NEAR_LIMIT`は独立した起動理由**で、索引を縮めるのが目的。索引を縮めないまま上限近傍が続く間は、`ARCHIVED`の有無にかかわらず毎回の`/wrapup`で起動する。`UNDECIDED`と`UNRESOLVED`だけでは起動しない
  - 上の張り替えをしても`comm -13`が空にならない
- **呼び方**: 上の照合まで終えてから、Skill toolで`claude-audit`を`memory <対象memory dirの絶対パス>`付きで起動する（`--confirm`を付けるかはモード表に従う）。返る区分は`修正した / attic退避した / 未対応 / invalid target`で、`未対応`は段6の未実施リストへ載せる
  - Skill toolから起動できなかった場合（toolが無い・skill名が解決できない・`skillOverrides`で無効化されている・起動時エラーで**変更が1件も入っていない**）は、`~/.config/claude/skills/claude-audit/SKILL.md`（絶対パス。他プロジェクトのセッションでは相対パスが解決しない）を読んで`memory`モードの手順をその場で実行する
  - 起動はしたが結果区分が返らず、変更が入った**または入ったか分からない**場合は**その場の再実行をしない**。二重適用になるため、段6へ「claude-audit途中終了・要手動確認」として載せる（変更ゼロを積極的に確認できないときはこちらに倒す）
- **`claude-audit`から戻ったら、`memcheck check`と`memcheck pairs`の前後比較をもう一度通してから段6へ進む**。auditがMEMORY.mdやリンクを変えているため、呼ぶ前の確認結果は無効になっている。**再検証が通らない、または検査不能（`memcheck`が3・4）ならcommitへ進まず、そこで止めてユーザーへ報告する**

### 6. やり残し総点検

- セッション内の「あとで対応」「必要なら実施します」等の約束・提案・保留、サブエージェント報告の「未対応の提案」「スコープ外」項目を洗い出し、未実施リストを提示する。**対応要否を確認するかはモード表に従う**
- **会話に出ない「状態に残ったもの」を、次の4つから候補として拾う**。拾うのは**このセッションの作業に属するものだけ**。他セッションの残りや、ユーザーが残すと言ったものは載せない。拾ったものは「状態から拾った候補」と印を付け、未実施と断定しない:
  - **未commit・未push**: 作業ディレクトリ（追加の作業ディレクトリを含む全て）の`git status --short`と、`git log @{u}..HEAD --oneline`。開始時の`gitStatus`にあった変更と、このセッションで作っていないcommitは「開始前から」と分けて載せる。upstream未設定のときは「upstream未設定」と1行だけ書き、未pushとは書かない
  - **worktree**: このセッションで`git worktree add`したものだけを`git worktree list`と照合する
  - **task-board**: 現在のセッションの一覧（`session`にこのセッションIDの先頭8桁を含む一覧と、このセッションで書いた一覧）だけを見る。手書きJSONの`status`は、`task_set`の結果や`.claude/task-board/overlay/`の提案で画面上は変わっていることがある。完了は`task_set`の呼び出し結果が正で、JSONの未完了を未実施と断定しない
  - **background実行**: このセッションが`run_in_background`・`nohup`で起動し、`ps -p`でまだ生きているもの。生存だけで未実施とは言えないので、何のための処理かを添えて「止めてよいか要確認」として載せる
- **セッション中に解決済み・不要になった保留項目は未実施リストから落とす**が、落とした事実は一覧に残し、**「どのcommitで/どの返信で解決したか」を1語添える**（ユーザーが漏れと意図的な除外を区別できるように）。「解決済み」のような抽象語で済ませない

### 7. 終了報告

1通目だけで、セッションを閉じる人に「終わったか・残ったものは何か」が届くようにする。詳細は合図を待って次のメッセージで出す。

- **最初の一文で終了状態を次の4語のどれかで言い切り、件数とcommitを添える**:

  | 状態 | 条件 | 書き方の例 |
  |---|---|---|
  | 完了 | 適用すべき変更をすべて適用し、検証が通り、残件が無い | 「完了。還元3件・削除1件、commit abc1234」「完了。メモリ2件を更新、commitなし（メモリはgit追跡外）」 |
  | 変更なし | このセッションで何も変更していない（還元候補が0件、または`confirm`で全候補を却下） | 「変更なし。還元候補は0件」 |
  | 中断 | 検証失敗・`claude-audit`途中終了・再検証が通らない・検査不能のまま削除済み、のいずれかで適用を途中で止めた | 「中断。索引の再検証が通らず、commitしていない」 |

- 残件があるときは、「完了」「変更なし」の後ろに件数を添える（「完了(残件2件)」「変更なし(残件1件)」）。`wrapup-recall`の取得失敗・未導入は残件に数える。「recall未導入で候補が0件」は「変更なし(残件1件)」になる
- commitの書き方: git追跡ファイル（skill/rule/CLAUDE.md/CLI）を変えたときは`commit <hash>`。git追跡外のメモリだけを変えたときは「commitなし（メモリはgit追跡外）」。実在しないcommitは書かない
- 次の行に、残件の件名を1行ずつ書く。無ければ「残件なし」と書く。中断のときは、止まった理由とユーザーに必要な操作を1行で書く
- 候補一覧の詳細・「既存資産が効いていない」の指摘・根拠は1通目に積まない。ユーザーが求めたときか合図の後に出す。ただし中断と要手動確認は、1通目に必ず入れる

## 関連

- 常時規約: 同チェックはタスク完了時にも都度行う（グローバルCLAUDE.md「対話・確認の規約」）
- 定期棚卸し（資産全体を意図的に総ざらいする重複・矛盾・陳腐化の掃除）は`/claude-audit`（こちらは蓄積後の掃除で全件を走査する）。wrapupは都度の還元で、削除も**このセッションが無効にしたもの、または作業中に偶然気づいた陳腐化**を対象とする — 全件の意図的な洗い出しはclaude-audit側の役割のまま変えない
