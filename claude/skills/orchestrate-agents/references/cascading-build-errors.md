# 連鎖するコンパイルエラーの一括診断

workerがビルドできない構成で提出物にコンパイルエラーがあるとき、1件見つけるたびに差し戻すと往復が線形に増える。メインが一時的に全件を修正して**完全なエラー一覧**を得てからrevertし、1回の差し戻しに畳む。

理由: コンパイラは最初のエラーで停止するため、後続のエラーは前を直すまで見えない。2026-08-30の実測では、この手順で4ラウンド分の差し戻しを1ラウンドに圧縮した(iOSアプリのフェーズBで、`specifier:`の誤用→タプルパターンの`let`漏れ→初期化前self捕捉→2件目の`specifier:`、という連鎖)。

## 手順

1. 編集前に対象ファイルの `git hash-object` を記録する(untrackedでも取れる)
2. エラーを1件直してビルドし直す。これを通るまで繰り返す
3. 全passしたらテストも実行し、「この修正群を当てれば通る」ことを確認する
4. **すべてrevertし、記録したhashと一致することを確認する**
5. 差し戻しパケットに全エラーと、メインが実測した「修正後は通る」事実を書く。**部分的な修正で別のエラーが残る組み合わせがあるなら明示する**(例: 片方だけ直すと別の欠陥が残る場合)

## 注意

revert漏れはworkerの提出物を汚染する。段5のfingerprint照合で検出されるが、手順4の自己照合で先に潰す。
