# Slack下書きの書式

送信は別規約(原則下書きで止める。`claude/CLAUDE.md`「対話・確認の規約」)。ここは文面の形だけを定める。

Slackの進捗報告・依頼への返信の下書きは、本人が送る形に合わせる。手順を渡す返信はコマンドと前提の一言だけにし、失敗時の挙動・後片付け・次の依頼の箇条は足さない。コマンドは相手が見慣れた形(`read -rs` ではなく `export A="..."`)で書く。対象名(repo名など)を1行目に置き、その下を環境・対象ごとの見出し行(例: 「prd 側」「dev 側」)で分け、各見出しの下を箇条書きにする。PRのURLは各見出しの最初の箇条にそのまま貼る。箇条は「適用済み。」「PR起票までが完了です。」のような短い言い切りにし、地の文の段落にしない。チャンネル名パターンなどの識別子は `code` で囲む。検証方法の注記・判断の理由・関連して済ませた作業・相手への依頼・発行日などの細部は入れない。完了報告なら各見出しの下はPRのURLだけでよい。分類ごとの状態と方針を並べる共有では、Slackの見出し(`#`)とテーブルを使い、「確認したいこと」のような質問だけの節を別に立てない。相手に対応や確認を頼む項目を並べる共有では、テーブルにせず、項目ごとにリンク付きの見出し箇条を立てて詳細を字下げ箇条で書く。対応済み・close済みの項目は載せない。複数repoをまとめて送るときはrepo名を見出し(`###`)にする。見た目は本人へのDMに送って確かめてから本番の宛先へ回す。`slack_send_message_draft` は見出し・テーブルを解釈しないので、見出しを使う投稿を下書きツールで作らない
