# herdr English Reply

別workspaceで動くAIエージェント宛の返信を、相手の最新メッセージを踏まえてカジュアルな英語に整える。添削結果だけでなく、選べる表現とそのニュアンス差も出す。

前提は `HERDR_ENV=1`。未設定なら対象paneを読めないので、その旨を伝えて停止する。herdrコマンドの詳細は `herdr` skillに従う。

## 実行mode

環境変数 `HERDR_PANE_ID` が**変数として存在しない**なら外部ヘルパーmode（herdrの外＝WezTermの別paneで常駐している）。存在するなら内部mode（herdr管理下のpane）。判定は空文字ではなく変数の有無で行う（`printenv HERDR_PANE_ID` の終了コードで確認できる）。

起動後の最初の応答で、どちらのmodeで動いているかを1行示す。外部modeではcwdの `CLAUDE.md`（herdrヘルパー専用の常設規則）が `herdr` skillの記述より優先される。

## ワークフロー

### 1. 対象workspaceを決める

既定は**focused追従**: ARGUMENTSが空なら、番号を聞かずに「focused追従で動く。返信案を送って」とだけ返す。以後、添削のたびに `herdr workspace list` で `focused: true` のworkspace（＝ユーザーがいまherdrで開いているspace）を対象にする。ユーザーがherdr側でspaceを切り替えれば、次の添削から自動的にそのspaceの会話を踏まえる。

`/herdr-english-reply <番号>`（例: `/herdr-english-reply 3`）のように番号（`herdr workspace list` の `number`）が渡された場合だけ、そのworkspaceに**固定**する。会話の途中で番号だけを送られた場合も固定へ切り替える（`0` または `auto` でfocused追従へ戻す）。

### 2. 対象paneを解決する

**添削のたびに毎回引き直す。** paneやworkspaceが閉じるとidは詰められて再利用されるため、前回のidをそのまま使うと別セッションを読む。

```bash
herdr workspace list
herdr pane list --workspace <workspace_id>
```

- focused追従: `focused: true` のエントリから `workspace_id` を取る。**前回と対象workspaceが変わっていたら、出力の冒頭に「(workspace <number>: <label>)」と1行添える**（読んでいる相手が切り替わったことの明示。毎回は出さない）
- 番号固定: `number` 一致のエントリから取る。初回に控えた `workspace_id` と食い違ったら黙って進めず、`label` を添えて対象が変わっていないか確認する
- pane一覧のうち `agent` フィールドを持つpaneが対象（nvim等のpaneにはこのフィールドがない）。複数あれば pane_id / agent / `terminal_title_stripped` を並べて選ばせる。0件ならその旨を伝えて聞き直す

### 3. 相手の最新返信を読む

```bash
herdr pane read <pane_id> --source recent-unwrapped --lines 80
```

TUI装飾・spinner・入力プロンプト行は捨て、エージェント側の**最新の実質的な発言**だけを文脈にする。途中で切れていたら `--lines` を増やす。まだ何も出力がない場合は文脈なしで添削してよいが、そのことを明示する。

ただし入力プロンプト行(未送信)がユーザー自身の伝えたい内容の下書きに見える場合は、機械的に読み捨てず、返信案の候補として扱ってよいか一言確認してから進める。ユーザーが `translate`（大小文字・表記揺れ問わず）とだけ送ってきた場合は、その確認を省略し、入力プロンプト行に残る未送信テキストを返信したい内容として直接処理する（手順4と同じ自動分岐: 日本語なら英訳、英語なら添削）。入力欄が空ならその旨を伝えて終える。

### 4. 添削または英訳する

**言語を見て自動で分岐する**: 入力が英語なら添削、日本語なら英訳する。ユーザーがどちらか指定する必要はない。どちらの場合も出力フォーマットは同じ。ユーザーが英作文できなくて日本語をそのまま送ってくるのは想定内なので、英語で書き直すよう促さない。逆に英語で書いてきたら、そのまま送れる品質かを添削で示す。

**そのままで送れるなら言う。** 文法・意味の誤りがなく、チャットでそのまま送って通じるレベルなら、無理に別案を主にしない。`Reply` にはユーザーの原文をそのまま入れる（大文字だけ直す等の体裁だけ変えた場合は、それが「変更」であることを Notes で一言示す）。Notes の冒頭で「そのままで問題ない」「このまま送ってよい」と明示する。代替表現は好みの差（大文字・`tell me` の直球さ・`still` で文脈に寄せる等）に留まるときは、必須ではなく「変えたいときだけ」の参考として1つまでに抑えるか、省略してよい。ユーザーが「どこがおかしい？」と聞いたときは、誤りがないなら誤りがないと先に言う。

**返信したい本文なのか、直前の提案へのコメントなのかを取り違えない。** 短い発言は両方の意味になりうる（例: 「そのままでいいや」は「Replyはこの案でいいから送る内容として使って」の意にも「直前の質問への回答」の意にも読める）。`"..."` や `「...」` で囲まれた文字列は常に「返信したい内容そのもの」として扱う。囲みがなく判別できない場合は、対象paneへの返信案として扱ってよいか一言確認してから進める。

**平易な英語を最優先する。** ユーザーが自分で読めて、次回は自分で書ける語彙に落とす。

- 中高レベルの語で言えることに難しい語を使わない（`utilize`→`use`、`ascertain`→`check`、`in the event that`→`if`）
- 凝ったイディオム・句動詞・比喩表現を持ち込まない。直球で言う
- 一文を短く切る。関係代名詞で伸ばすより2文に割る
- 省略形・命令形でよい。`I would appreciate it if you could` 系の枕は落とす
- ビジネスメール調・教科書英語にしない。逆にスラングや皮肉を足すのも禁止
- コード識別子・パス・技術用語・エラーメッセージは原文のまま残す
- 「よしなに」「いい感じに」のような曖昧語は具体的な英語に落とす。落とし方が複数あるなら断定せず選択肢として出す
- 日本語の専門用語・文法概念（固有名詞・比喩・敬語等）を英語に直訳しようとして学術寄りの単語（`proper noun`等）に逃げない。日常語で言い換えられないか先に検討する

## 出力フォーマット

説明は日本語、返信本文は英語。`Reply` はそのまま貼れる完成文をコードブロックで出す。

- **Context** — 相手の最新返信の要点を1〜3文。長い引用はしない
- **Reply** — コピペ用の英文
- **和訳** — Replyの意味を日本語で1〜3文。意訳でよいが、英語の言い回しと食い違わないようにする
- **Notes** — **箇条書き**で書く。変更した箇所ごとに「原文 → 直し」と、**何が文法的に問題だったか／なぜその形にしたか**を短く説明する（冠詞・時制・不完全文・主語と動詞の一致など）。文法上問題なく好み・自然さだけの変更なら「文法は問題なし。〜の方が自然」と明示する。原文がそのままでよいときは「そのままでよい」と1項目で書く。代替表現は1〜2個を別項目にし、各1行でニュアンス差を添える。代替英文がある場合はその直後に和訳を1行添える
- **Structure** — Reply文の型と、基礎語彙を超える単語の意味を日本語で毎回添える。聞かれなくても毎回出す
  - 文の型: `動詞+目的語+補語`のような型なら型の名前と他の用例を示す
  - 単語: 中学英語レベルを超える単語には1行で意味を添える（例: `jargon`＝「専門的で分かりにくい言葉」）。文法・言語学の用語（固有名詞・副詞など）を使うときはその用語自体もかみ砕く
  - 迷ったら「説明する」側に倒す。ユーザーが知っている前提を置かない

「もっとカジュアルに」「短く」「この単語は残して」などの指示が来たら、同じフォーマットで出し直す。

`Reply` の文構造・文法を聞かれたら、都度Context/Reply/Notesの形式には拘らず、該当箇所を要素分解して日本語で説明する（例: 決まり文句なら由来と直訳、`動詞+目的語+補語`のような型なら型の名前と他の用例）。平易な英語を保つ方針と同様、文法用語も必要最小限にする。

## 禁止事項

**対象paneへ勝手に送信しない。** 添削の完了は送信の許可ではない。送信可否はmodeで分かれる。

- 内部mode: `pane send-text` / `pane run` は、ユーザーが明示的に送信を頼んだときだけ実行する
- 外部ヘルパーmode: `pane send-text` / `pane run` を**明示的に頼まれても実行しない**。「元のpane（herdr側）で送信してください」と案内する。他のherdr変更系コマンドも同様

## 使用例

`/herdr-english-reply` → 「focused追従で動く。返信案を送って」と返して待機。以後、添削のたびにいまherdrで開いているspaceのエージェントpaneを読む。

`/herdr-english-reply 3` または ユーザー: `3` → workspace 3 に固定して待機（`0` か `auto` で追従に戻る）。

ユーザー: `それで進めて。終わったら結果だけ見せて`

→ paneを読み、Context「実装方針に合意済みで、テストを回すか確認してきている」／Reply `Sounds good, go ahead. Just show me the results when you're done.`／和訳「了解、そのまま進めて。終わったら結果だけ見せて」／Notes「別案 `OK, please go ahead. Send me the results at the end.`（少し落ち着いた言い方）／和訳「OK、進めて。最後に結果を送って」」

ユーザー: `translate`

→ 対象paneを読み直し、入力欄に残る未送信テキストをそのまま返信案として英訳する（内容の確認は行わない）。
