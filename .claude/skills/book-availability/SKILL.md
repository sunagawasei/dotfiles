# 書籍在庫・蔵書調査 → Notion反映

Notionの読書リストページを起点に、指定サイトの在庫・蔵書を調べ、結果をページ本文のテーブルとデータベースプロパティの両方へ反映する。

## 前提

- Notion MCP（`notion-fetch` / `notion-update-page`）が使えること
- 応答は日本語
- 在庫は**調査時点の目安**。必ず確認日を書く

## デフォルト調査先

ユーザーがサイトを指定しないときは次を調べる。

| 区分 | 対象 | 確認URLの種別 |
|------|------|---------------|
| 書店 | くまざわ書店（球陽堂 メインプレイス店） | 店舗別在庫詳細 |
| 図書館 | 沖縄県立図書館 | カーリル ISBN 検索 |
| 図書館 | 那覇市立図書館 | カーリル（沖縄） |
| 書店 | ジュンク堂書店 那覇店 | 商品ページ |
| 古本 | バリューブックス | ISBN 検索 |

追加・変更の指定があればそれに従う。

## ワークフロー

```
進捗:
- [ ] 1. Notionページから書籍情報を取得
- [ ] 2. ISBN を確定
- [ ] 3. 各サイトを調査
- [ ] 4. Notion にテーブル追記・更新
- [ ] 5. 読書リストの在庫・蔵書プロパティを更新
- [ ] 6. fetch で反映確認
```

### 1. 書籍情報の取得

`notion-fetch` でページを取得する。

- **タイトル**: `properties` の `タイトル`
- **ISBN**: ページメモの `978...` を最優先。無ければくまざわ書名検索や openBD。NDL の書名検索は別書籍に当たることが多いので使わない
- 特定した ISBN は openBD の書名・著者と Notion タイトルを照合する
- シリーズ親（哲学史入門、森の生活、禅とオートバイ 等）は第1巻 ISBN で代用する
- 雑誌は ISBN-13 ではなく JAN のことがある（例: 建築知識）
- **書影**: `content` 内の画像 URL（テーブル挿入位置の目印）

### 2. 各サイトの調査

並列で調べ、**状況**と**ユーザーが開ける確認URL**を揃える。

#### くまざわ書店（球陽堂）

```bash
curl -sL -A "Mozilla/5.0" \
  "https://www.search.kumabook.com/kumazawa/html/products/list?mode=books&name={ISBN}"
```

- 商品詳細 URL（`products/detail/{id}?mode=books&name={ISBN}`）を控える
- 詳細ページで対象店舗名（例: `球陽堂書房 メインプレイス店`）の `在庫：○ / △ / ×` を読む
- 一覧の「選択店舗在庫」は集計表示のことがある。**店舗名が一致する詳細の表示を優先**

#### カーリル（図書館）

```bash
# 初回
curl -sL "https://api.calil.jp/check?isbn={ISBN}&systemid={SYSTEMID}&callback=no"
# session 取得後、continue が 0 になるまで 2〜3 秒間隔でポーリング
curl -sL "https://api.calil.jp/check?session={SESSION}&callback=no"
```

| 図書館 | systemid |
|--------|----------|
| 沖縄県立図書館 | `Okinawa_Pref` |
| 那覇市立図書館 | `Okinawa_Naha` |

`libkey` の解釈:

- キーあり + `貸出中` / `予約中` → テーブル **所蔵あり（貸出中）**、プロパティ **貸出中**
- キーあり + `貸出可` 等 → テーブル **所蔵あり（貸出可）**、プロパティ **貸出可**
- キーあり + `館内のみ` → テーブル **所蔵なし**、プロパティ **所蔵なし**（館内限定はフィルタ上「借りられない」）
- `libkey` が空 `{}` → **所蔵なし**

確認URL:

- 県立・個別: `https://calil.jp/search?isbn={ISBN}`
- 沖縄ローカル: `https://calil.jp/local/okinawa`

Web UI は bot 対策でブロックされることがある。**API 結果を正とする**。

#### 丸善ジュンク堂（那覇店）

商品ページ: `https://www.maruzenjunkudo.co.jp/products/{ISBN}`

店舗在庫 API（商品ページ JS 内。変更されたら HTML から再取得）:

```bash
curl -sL \
  "https://api-item-info-ttmpxhtqra-an.a.run.app?access_key={KEY}&jan_isbn={ISBN}&type=2&store_code=70050"
```

- `70050` = ジュンク堂書店 那覇店
- 応答は **配列**。dict として読むと全部 0 になる。配列から `stock_quantity` を取る
- `stock_quantity > 0` → **在庫あり（N冊）**
- 0 または空 → **在庫なし**
- ネットストアの「売り切れ」と店頭在庫は別。店舗行には店頭在庫を書く

#### バリューブックス

```bash
curl -sIL -A "Mozilla/5.0" -o /dev/null -w "%{url_effective}" \
  "https://www.valuebooks.jp/search?keyword={ISBN}"
```

- 旧 URL `/s?keyword=` は 404。正は `/search?keyword=`
- リダイレクト先に `/bp/` があれば **在庫あり**、なければ **在庫なし**
- `/bp/` 判定はやや甘め。目安として使う

### 3. Notion への反映

`notion-update-page` を使う。反映前に必ず `notion-fetch` で現状を読む。

ユーザーが「プロパティ埋めて」などプロパティだけを指定したら本文テーブルは書かない。テーブル・貼り付け・詳細URLの指定があるとき、または指定が無いときは本文も更新する。

#### 新規追加

書影画像の直後に次を挿入（`update_content` で `old_str` = 書影行）。

```markdown
## 在庫・蔵書状況
確認日: YYYY-MM-DD
<table header-row="true" fit-page-width="true">
	<tr>
		<td>サイト</td>
		<td>状況</td>
		<td>確認URL</td>
	</tr>
	<tr>
		<td>{サイト名}</td>
		<td>{状況}</td>
		<td>[{リンク表示名}]({URL})</td>
	</tr>
</table>
```

#### 既存テーブルがある場合

`## 在庫・蔵書状況` から `</table>` までを丸ごと置換し、**確認日を当日に更新**する。サイト行の追加・削除もここで行う。

#### 状況の書き方（統一）

| 種別 | テーブル表記 | プロパティ値 |
|------|--------------|--------------|
| 書店・在庫あり | `在庫あり（1冊）` | `在庫あり` |
| 書店・わずか | `残りわずか（△）` | `残りわずか` |
| 書店・なし | `在庫なし（×）` | `在庫なし` |
| 図書館・所蔵・貸出中 | `所蔵あり（貸出中）` | `貸出中` |
| 図書館・所蔵・貸出可 | `所蔵あり（貸出可）` | `貸出可` |
| 図書館・なし | `所蔵なし` | `所蔵なし` |
| 古本・なし | `在庫なし` | `在庫なし` |

冊数などの詳細は本文テーブルに残し、プロパティはフィルタ用の短い値にする。

#### プロパティへの反映

テーブル更新のあと、同じページで `update_properties` する。対象は読書リストのデータソース `collection://28c21568-b2b7-8103-a518-000bf3a5a29f`。

| プロパティ | 型 | 値 |
|------------|----|----|
| くまざわ | select | 在庫あり / 残りわずか / 在庫なし |
| ジュンク堂 | select | 在庫あり / 残りわずか / 在庫なし |
| 県立図書館 | select | 貸出可 / 貸出中 / 所蔵なし |
| 那覇市立 | select | 貸出可 / 貸出中 / 所蔵なし |
| バリューブックス | select | 在庫あり / 在庫なし |
| 在庫確認日 | date | 調査日（`date:在庫確認日:start` + `date:在庫確認日:is_datetime` = 0） |

日付キーはコロン直後に空白を入れない。`"date: 在庫確認日:start"` はプロパティ名 `" 在庫確認日"` を探し 400 になる。

一括更新は先に 1 件を `allow_async: false` で通し、残りは `allow_async: true` のあと `notion-get-async-task` で succeeded を確認する。

プロパティが無い場合は `update_data_source` で上記を追加してから値を入れる。既存オプション以外の値は作らない。

### 4. 確認

`notion-fetch` でテーブル・確認日・リンクと、在庫・蔵書プロパティが意図どおりか確認してから完了報告する。

## ユーザーへの報告

チャットでは次を簡潔に伝える。

1. 書名・ISBN
2. 各サイトの状況（テーブル要約）
3. Notion ページ URL
4. 在庫は調査時点の目安である旨（1行）

## 注意

- くまざわ・カーリルは表示と実在庫がずれることがある
- バリューブックスの `/bp/` 判定はやや甘い
- シリーズ親ページの ISBN は第1巻の代用
- 丸善の `access_key` や店舗コードはサイト変更で無効化されうる。そのときは商品ページ HTML を再解析する
- ユーザーが「調べられる？」とだけ聞いた場合は、可能であることと制約を先に答え、**貼り付けまで依頼されていなければ Notion は更新しない**
- ユーザーが貼り付けまで依頼した場合のみ Notion を更新する
